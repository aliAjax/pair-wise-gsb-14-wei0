# 油品价格维护

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Naive UI
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 调价审批流程

数据不再是一张可直接改的列表，而是「调价单 → 价格版本 → 回滚记录」的完整链路，保存在浏览器 localStorage 中（方便后续替换为后端接口）。

1. **站长提交调价单（待复核）**
   - 按当前最新版本价格拟价，提交时把整张价目表存为**价格快照**，并记录基线版本号、提交人、生效日期。
   - 快照一经提交即冻结，不再受之后任何价格改动影响。
2. **主管复核**
   - 通过时按调价单里**提交时的快照**生成一个追加的新版本（历史版本不可修改），版本上记录操作人、生效日期、来源单号和审批意见。
   - 驳回只更新单据状态，不产生新版本。
3. **回滚**
   - 对任一历史版本执行回滚，会取该版本**审批时的原始快照**生成新版本，并写一条回滚记录（回滚路径、操作人、原因、生效日期）。不修改、不删除任何历史版本。
4. **并发控制（白班/夜班互不覆盖）**
   - 状态带单调递增的版本令牌 `rev`，审批/回滚都带打开弹窗时的令牌做**乐观并发校验**。
   - 若另一班在这期间已发版：旧窗口提交时会看到「版本已变化」，单据标记为**版本冲突**，原复核人与审批意见保留，但绝不会用旧快照盖掉对方刚发布的价格；需要调整时由站长按最新版本重新提交。
   - 多个标签页之间通过 `storage` 事件实时同步。

## 目录

- `src/types.ts`：调价单、价格版本、回滚记录领域模型
- `src/store.ts`：Pinia store，提交/复核/回滚与乐观锁逻辑
- `src/components/`：提交表单、单据列表、复核弹窗、版本与回滚面板、快照对比表
- `scripts/smoke.ts`：并发场景冒烟测试
  `npx esbuild scripts/smoke.ts --bundle --platform=node --format=esm --outfile=scripts/smoke.mjs && node scripts/smoke.mjs`
